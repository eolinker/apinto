# 访问层级鉴权插件 (access-hierarchy) 单元测试场景说明文档

为了确保“通用级联鉴权引擎”在提供超强自定义灵活性的同时，拥有工业级的稳定度与高性能，我们针对该插件编写了覆盖率高达 **98.4%** 的完整测试套件。

为了便于业务开发与运维人员快速理解，本篇文档完全基于实际业务名词——**“消费者/渠道”（对应 App）**、**“用户租户”（对应 Parent Node）**、**“资源组”（对应 Child Node）**以及**“最终资源”（对应 Target）**，为您梳理所有的单元测试场景及其设计意图：

---

## 💡 概念映射字典

| 底层通用抽象 (代码设计) | 实际业务场景名词 (业务对齐) | 核心作用 |
| :--- | :--- | :--- |
| **App** | **消费者 / 渠道** | 发起请求的主体（例如：某个外部合作商渠道、某个前端 APP 消费者）。 |
| **Child Node** | **资源组** | 资源的逻辑聚合容器。消费者通常通过加入资源组来间接获得其中的资源。 |
| **Parent Node** | **用户租户** | 更高维度的账号边界。资源组一般归属于特定的用户租户。 |
| **Target** | **最终资源 (Resource)** | 客户端最终想访问的 API 接口、路由或数据服务。 |

---

## 一、 基础“防空”判定与边界防御

在处理任何复杂的级联检索前，系统必须具备极强的鲁棒性，防止脏数据或空请求把系统带垮。

| 测试函数/用例名 | 对应业务实体描述 | 现实业务场景说明 | 期望结果 |
| :--- | :--- | :--- | :--- |
| empty app or resource ID | 消费者或资源 ID 为空 | 客户端请求时，网关提取不到该“消费者/渠道”的标识，或者不知道它想访问哪个“最终资源”（如提取出来的 Resource 标识为空）。 | 安全拒绝 (返回 false) |
| no app groups bound | 消费者未加入资源组 | 该“消费者/渠道”在数据库中未和任何“资源组”建立绑定关系，是个无主的孤立账号。 | 安全拒绝 (返回 false) |
| group_meta not found | 资源组档案缺失 | 消费者加入了某个资源组，但该资源组在系统的“资源组元数据表”中没有任何注册档案（属于脏数据）。 | 安全拒绝 (返回 false) |

## 二、 基础直接授权与“有效期”判定

消费者通过加入特定资源组，获得该资源组直接拥有的资源访问权。同时，我们必须严密监控各个绑定关系的“有效期时间戳”，防止过期访问。

| 测试函数/用例名 | 对应业务实体描述 | 现实业务场景说明 | 期望结果 |
| :--- | :--- | :--- | :--- |
| simple explicit resource match pass | 直接授权正常访问 | 消费者绑定的资源组为“直接授权”模式，且该资源组直接拥有该最终资源，且绑定关系均在有效期内。 | 安全放行 (返回 true) |
| simple explicit resource expired app-group | 消费者与资源组绑定过期 | 该消费者虽然曾被加入该资源组，但其“入组期限时间戳”已经到期。 | 拦截阻断 (返回 false) |
| simple explicit resource expired group-resource | 资源组对该资源的授权到期 | 消费者与资源组的绑定虽然未过期，但该资源组拥有的这款资源的“使用期限时间戳”已经到期。 | 拦截阻断 (返回 false) |
| explicit_resources resource not found | 资源不在资源组授权列表中 | 资源组是“直接授权”模式，但该资源组拥有的所有资源列表中，并没有消费者想访问的那款目标资源。 | 拦截阻断 (返回 false) |

## 三、 名词自定义与“平滑降级”向下兼容性

我们既支持全新的**高度自定义层级命名**，也支持对老版本（租户/资源组）的**无缝向下兼容**。

| 测试函数/用例名 | 对应业务实体描述 | 现实业务场景说明 | 期望结果 |
| :--- | :--- | :--- | :--- |
| TestAccessHierarchy_CustomConfig | 自定义名词映射 | 系统管理员在控制台重构了名词前缀（将节点映射为“岗位”，将父节点映射为“部门”），系统能完美解析并重新对齐所有存储前缀。 | 正确加载并映射新前缀 |
| TestAccessHierarchy_BackwardCompatibleConfig | 历史配置平滑回退 | 生产环境上使用的是老版本的配置文件，里面全是老名词（如 TenantGroups 等）。插件初始化时自动进行兼容映射，零损升级。 | 完美向下兼容旧名词前缀 |
| TestAccessHierarchy_CustomConfigExecution | 自定义模式执行测试 | 在完全使用全新自定义的消费者、渠道、资源组的配置下，成功执行一遍完整的鉴权流程。 | 新前缀鉴权完全成功 |

## 四、 跨实体的“用户租户 ➔ 资源组”级联向上授权

消费者绑定的“资源组”声明自身不直接配置权限，而是“跟随/继承”其归属的“用户租户”所拥有的资源。

| 测试函数/用例名 | 对应业务实体描述 | 现实业务场景说明 | 期望结果 |
| :--- | :--- | :--- | :--- |
| follow tenant mode pass | 跟随并继承租户资源 | 消费者绑定的资源组配置为“跟随租户”模式，其所属的“用户租户”旗下拥有资源组B。而资源组B旗下直接配置了最终资源的访问权。 | 级联继承通过 (返回 true) |
| follow tenant mode filter non-explicit... | 租户旗下关联了非直接授权组 | 消费者绑定的资源组归属于某个用户租户，该租户虽然关联了另一个资源组B，但资源组B的授权模式并不是“直接授权”模式。 | 拦截阻断 (返回 false) |
| multi-level hierarchical granted groups... | 租户跨级授权/被动级联 | 消费者所在的资源组跟随“子租户”，子租户由于合作关系被授权了“父租户”的关联资源，父租户又拥有“祖父租户”的分组。层层跨越级联。 | 穿透级联放行 (返回 true) |

## 五、 自继承“无限级套娃”与有向图“死循环”防御

节点（资源组、用户租户、甚至消费者渠道自身）不仅能继承不同类型的实体，还支持进行纯粹的“同类自继承”（例如：一个渠道继承另一个渠道，或一个资源组隶属于另一个资源组，支持无限级嵌套）。在此情况下，系统内置了强大的防死循环算法。

| 测试函数/用例名 | 对应业务实体描述 | 现实业务场景说明 | 期望结果 |
| :--- | :--- | :--- | :--- |
| InfiniteDepthSelfInheritance | 同级渠道无限自继承 | 模拟渠道自继承链：渠道1 继承 渠道2，渠道2 继承 渠道3，最后最顶级的 渠道3 直接拥有某个资源的权限。 | 10层内无上限递归放行 (返回 true) |
| cycle detection group cycle | 资源组循环继承防御 | 运营人员配置失误，导致资源组形成了环状循环：资源组1 的父级是 资源组2，而 资源组2 的父级又是 资源组1。 | 图搜索自动切断并报警 (返回 false) |
| cycle detection tenant cycle | 用户租户授权死循环 | 配置失误导致租户授权自环：用户租户1 跨级授权给 用户租户2，而 用户租户2 又反向授权给了 用户租户1。 | 图搜索自动切断并报警 (返回 false) |
| InfiniteDepthSelfInheritanceCycle | 自继承角色无限环判定 | 配置失误导致自继承环：渠道1 继承 渠道2，而 渠道2 反向继承 渠道1。 | 图搜索自动切断并报警 (返回 false) |

## 七、 性能基准极限测试 (Benchmarks)

为了保证消费者在大并发请求接口（最终资源）时，网关的鉴权耗时处于极佳状态，我们设计了三组 Benchmark：

BenchmarkHandler_Check_Simple-10                 # 场景：最常见的单层资源组直接授权，消费者直接刷卡。
BenchmarkHandler_Check_DeepInheritance-10        # 场景：3层用户租户/渠道链式自继承的深度级联寻路。
BenchmarkHandler_Check_10LevelsComplex-10         # 场景：10层超深用户级联套娃自继承 + 每层多达4个干扰资源组分支节点的图寻路遍历与回溯。

### 📈 极限性能表现一览

| 基准测试场景 | 单次查找耗时 (ns) | 对应 QPS 换算 (单核物理极限) | 内存分配开销 | 核心评估 |
| :--- | :--- | :--- | :--- | :--- |
| 单层直接授权 | ~257 ns (0.00025 毫秒) | ~388 万 QPS | 64 B/op (3 allocs) | 耗时近乎于零，无任何高并发压力。 |
| 3层垂直自继承 | ~627 ns (0.00062 毫秒) | ~159 万 QPS | 232 B/op (11 allocs) | 即使跨越 3 级继承（如消费者 ➔ 资源组 ➔ 用户租户），依然在毫秒级以下完成。 |
| 10层极深级联 + 干扰分支 | ~2587 ns (0.0025 毫秒) | ~38.6 万 QPS | 1.8 KB/op (47 allocs) | 遇到极度恶劣、包含大量无效旁支图回溯的配置，计算开销仍极其轻微。 |
